================================================================
Demo and failure scenarios
================================================================

A. Kubernetes self-healing: take down a pod
------------------------------------------
kubectl -n tfakkarni get pods
POD="$(kubectl -n tfakkarni get pod -l app=frontend -o jsonpath='{.items[0].metadata.name}')"
kubectl -n tfakkarni delete pod "$POD"
kubectl -n tfakkarni get pods -w
kubectl -n tfakkarni rollout status deployment/frontend --timeout=180s

Talking point: the ReplicaSet creates a replacement pod automatically.

B. Restart a service cleanly
----------------------------
kubectl -n tfakkarni rollout restart deployment/api-gateway
kubectl -n tfakkarni rollout status deployment/api-gateway --timeout=300s
kubectl -n tfakkarni logs deploy/api-gateway --tail=120

Talking point: controlled rollout without deleting Kubernetes objects.

C. Show logs, events, and diagnosis commands
--------------------------------------------
kubectl -n tfakkarni logs deploy/config-service --tail=120
kubectl -n tfakkarni logs deploy/tracking-service --tail=120
kubectl -n tfakkarni describe pod -l app=api-gateway
kubectl -n tfakkarni get events --sort-by=.lastTimestamp | tail -40
kubectl -n tfakkarni get pods --field-selector=status.phase!=Running

D. Simulate bad image, then rollback
------------------------------------
kubectl -n tfakkarni set image deployment/frontend frontend=thelime1/tfakkarni:bad-demo-image
kubectl -n tfakkarni rollout status deployment/frontend --timeout=90s || true
kubectl -n tfakkarni get pods
kubectl -n tfakkarni describe pod -l app=frontend

# Recover
kubectl -n tfakkarni rollout undo deployment/frontend
kubectl -n tfakkarni rollout status deployment/frontend --timeout=300s

Talking point: Kubernetes exposes ImagePullBackOff and rollback restores service.

E. Scale service down to show outage, then restore
--------------------------------------------------
kubectl -n tfakkarni scale deployment/api-gateway --replicas=0
kubectl -n tfakkarni get pods -l app=api-gateway
curl -i "http://${NODE_IP}:30090/actuator/health" || true

# Recover
kubectl -n tfakkarni scale deployment/api-gateway --replicas=1
kubectl -n tfakkarni rollout status deployment/api-gateway --timeout=300s
curl -i "http://${NODE_IP}:30090/actuator/health"

F. Port-forward for local debugging
-----------------------------------
kubectl -n tfakkarni port-forward svc/frontend 8080:80
# Open http://localhost:8080

kubectl -n tfakkarni port-forward svc/api-gateway 9090:9090
# curl -i http://localhost:9090/actuator/health

G. Local Docker container failure and recovery
----------------------------------------------
docker compose -f docker-compose.backend.yml up -d
docker stop tfakkarni-tracking
docker ps -a --filter "name=tfakkarni-tracking"
docker compose -f docker-compose.backend.yml restart tracking-service
docker compose -f docker-compose.backend.yml logs --tail=80 tracking-service
